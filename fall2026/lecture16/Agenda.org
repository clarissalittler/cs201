** Everything is a file (descriptor)
 + =fdStandard.c=: 0, 1, and 2 are already open -- who decided what they are?
   + Run it with =>=, =2>=, and a pipe
 + =fdCat.c=: the same copy loop on =sample.txt=, =/proc/cpuinfo=, =/dev/null=, =/dev/stdin=
   + What does read do on a directory?
 + =fdDevices.c=: =/dev/urandom=, =/dev/zero=, =/dev/null= are drivers, not data
 + =fdTable.c=: files, pipes, and devices in one descriptor table
   + =/proc/self/fd= lets us look at our own table
   + Which number does the next =open= get?
** Pipes and redirection are just descriptor tricks
 + =fdPipe.c=: a pipe is a file with no name
   + EOF only when /every/ write end is closed -- what happens if we forget one?
 + =fdRedirect.c=: =dup2= then =exec= is how the shell does =ls -l > listing.txt=
** The FILE API
 + A =FILE*= is a descriptor plus a buffer plus some conveniences
 + =stdioOpen.c=: modes, checking for =NULL=, =perror=
 + =stdioLines.c=: =fgets= reads a line /or/ as much as fits
   + Change =LINE_SIZE= to 16 and count the calls
 + =stdioChars.c=: =fgetc= and why =c= has to be an =int=
 + =stdioFormatted.c=: =fprintf= and =fscanf= with a text file
 + =stdioBinary.c=: =fwrite= and =fread= copy raw bytes -- look at them with =xxd=
 + =stdioSeek.c=: =fseek=, =ftell=, =rewind=, and why a pipe can't seek
** Buffering: when do our bytes actually leave the program?
 + =stdioBuffering.c=: run it to the terminal, then pipe it into =cat=
 + Line buffered, fully buffered, unbuffered
 + =fflush=, and what happens to the buffer if the program crashes
 + =stdioFileno.c=: =fileno= and =fdopen= connect the two layers
** Putting it together
 + =procSelf.c=: the kernel describes our process as a text file, and we read it with =fgets=
