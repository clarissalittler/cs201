* Agenda
** Two kinds of memory trouble
 + A cache miss isn't the same thing as an invalid memory access
 + Remember the parent and child with separate copies of a variable?
** Virtual addresses
 + The address in your program isn't directly a location in physical RAM
 + Pages, page tables, and offsets
 + The TLB caches translations
** Follow one address
 + Use 256-byte pages for this example
 + Virtual address =0x1234=
   + Page number =0x12=
   + Offset =0x34=
 + Map virtual page 0x12 to physical page 0xAB
 + The physical address is =0xAB34=
 + Now change whether the page is present, or whether we're allowed to write it
** Page faults
 + Sometimes the kernel can bring in the page and let us continue
 + Sometimes the access isn't valid, and the kernel delivers SIGSEGV
 + The MMU detects the translation/protection problem; the kernel handles it
** Copy-on-write
 + =fork_lifecycle.c= as a reminder of the observable behavior
 + Parent and child can initially share backing pages
 + A write can require a separate copy
 + That saves eager copying; it doesn't make fork free or instantaneous
