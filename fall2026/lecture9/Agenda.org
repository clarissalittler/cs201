* Agenda
** Processes, briefly revisited
 + Each one has a pid and its own execution state
 + We can ask the operating system to notify another process
** Signals
 + Sending a signal from the terminal
 + Default actions, installed handlers, blocked signals
 + A signal can be pending while it's blocked
 + Standard signals can coalesce; they aren't a queue of messages
** Receiving a signal
 + =signal_wait.c=
 + Run it in one terminal; send SIGUSR1 from another
 + Look at how small the handler is
   + Set a =volatile sig_atomic_t= flag
   + Return
   + Main does the printing
 + =printf= doesn't belong in the handler
** The annoying part: waiting
 Suppose we check a flag and then call pause.

 What if the signal arrives /between/ those two things?
 + The handler runs and returns
 + Then we go to sleep, waiting for something that already happened
 + =sigModernWay.c= has this check-then-pause problem
** Blocking and unblocking signals
 + =blockSignals.c= as another look at masks
 + In signal_wait, keep the signal blocked while checking the flag
 + =sigsuspend= temporarily changes the mask and waits
 + When it returns, check the flag again
 + Trace the case where the signal arrives before the wait
** Some things signals don't let us do
 + SIGKILL and SIGSTOP can't be caught or blocked
 + Returning from a handler doesn't magically repair the instruction that faulted
 + We can leave the signal duels and fault-catching examples for later
