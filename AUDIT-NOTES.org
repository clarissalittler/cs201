* Overview
These notes document recurring technical issues found across multiple terms of CS201, based on a comprehensive audit of all lecture files, examples, and guides. Use this as a checklist when preparing materials for a new term.

* Assembly: Recurring Bugs
** .long / 64-bit register mismatch (most common)
When =.long= (32-bit, 4 bytes) data is accessed with 64-bit register operations, the CPU reads 8 bytes from a 4-byte slot, producing garbage results.

This shows up in two forms:

*** Array access with wrong scale factor
#+begin_example
  arr1:   .long 1,2,3,4
  add (%rbx,%rcx,4),%rax    # BUG: reads 8 bytes per element, not 4
#+end_example

Fix: use =.quad= with scale 8, or use =addl= with =%eax=.

*Affected files (unfixed):*
- =spring2025/video3/data2.s=
- =winter2025/lecture4/data2.s=, =data3.s=

*** Single variable loaded into 64-bit register
#+begin_example
  num1:   .long 200
  mov num1(%rip),%rdi        # BUG: reads 8 bytes from 4-byte variable
#+end_example

Fix: use =.quad=, or =movl num1(%rip),%edi= (zero-extends to =%rdi=).

*Affected files (unfixed):*
- =spring2025/video3/data0.s=, =data1.s=
- =winter2025/lecture4/data1.s=

*Fixed [2026-07-04]:*
- =assembly-examples/02-data/02-data-section.s=, =03-data-types.s= (now =movl= into =%edi=; these matter because the README sends beginners to =assembly-examples/=)

*** Prevention
Default to =.quad= and scale 8 when writing examples. Only use =.long= when specifically teaching 32-bit operations, and use =l= suffixes consistently (=movl=, =addl=, =%eax=/=%edi=).

** movb without zero-extension in readInt/parseInt
Every copy of =readInt= across all terms has:
#+begin_example
  movb (%rdi,%rcx,1),%r8b   # only sets low byte
  sub $'0',%r8               # operates on all 64 bits (upper bytes = garbage)
#+end_example

Fix: =movzbl (%rdi,%rcx,1),%r8d= (zero-extends byte into full register).

*Affected files (unfixed):*
- =fall2024/lecture8/readInt.s=, =readInt2.s=, =readInt3.s=
- =fall2025/lecture08/readInt.s=
- =spring2025/assembly/readInt.s=

*Fixed:*
- =assemblyGuide.org=
- =assembly-examples/05-io/02-read-integer.s=

** %rbx clobbered without push/pop
=%rbx= is callee-saved. Functions that modify it must save/restore it. Every copy of =readInt= and =writeInt= across all terms violates this.

*Affected files (unfixed):*
- =fall2024/lecture8/readInt3.s=, =stolenWriter.s=
- =fall2025/lecture08/readInt.s=, =writeInt.s=, =writeIntBad.s=
- =spring2025/assembly/readInt.s=, =writeInt.s=
- =winter2025/lecture7/leaQuestion.s=

*Fixed:*
- =assemblyGuide.org=
- =assembly-examples/05-io/02-read-integer.s=

** fd=0 for write syscall (should be fd=1)
Write syscall needs fd=1 (stdout), not fd=0 (stdin). Works on terminals but semantically wrong.

*Affected files (unfixed):*
- =spring2025/assembly/echoInt.s= (3 instances), =echoInt2.s=, =stacky.s=
- =winter2025/lecture5/labelTest.s= (2 instances), =echo.s=, =echoBroken.s=

Note: =winter2025/lecture5/echo.s= has read and write fds *completely swapped* (reads from stdout, writes to stdin).

*Fixed:*
- =assemblyGuide.org= (anonymous labels example)

** Syscall register convention vs function calling convention
The 4th /syscall/ argument goes in =%r10=, not =%rcx=. This is because =syscall= clobbers =%rcx= (saves =%rip= there). The 4th /function/ argument is =%rcx= per the System V ABI.

Winter 2025 lectures 5 and 6 have the syscall argument list showing =%rcx= as 4th argument. None of the class examples use more than 3 syscall arguments so this never causes a real bug, but it's technically wrong and could confuse students who look it up later.

* C: Recurring Patterns
** Missing wait() after fork() (most common, 45 files)
Recurs every single term. Many are intentional early demos, but persists into IPC and signal examples where zombie processes matter.

** Unchecked fork() return value (22 files)
The =-1= error case is never checked in raw lecture demos. Commented tutorial versions do check it. Recurs every term.

** Missing #include <unistd.h> (18 files)
Files that call =sleep()=, =fork()=, =read()=, =write()=, =close()= without the header. Biggest cluster is =file-intro/= (7 files).

** int addrlen instead of socklen_t (winter 2025 only)
All 8 socket files in =winter2025/lecture12/= use =int addrlen= with a =(socklen_t*)= cast. Fixed in fall 2025 and =socket-examples/=.

** Thread-unsafe server pattern (ipc-lecture/ only)
=ipc-lecture/echoserver.c= has:
- Global =char buffer[1024]= shared across all client threads
- Passes =&newSocket= (loop variable address) to threads instead of malloc'd copy
- Unreachable =close()= calls after =while(1)= loop

Corrected versions exist in =socket-examples/= and =fall2025/sockets-lecture/=.

** #include "stdio.h" instead of <stdio.h> (fall 2025 only)
47 out of 72 non-commented source files in fall2025 use quoted includes for system headers. Every other term uses angle brackets. The commented versions of the same files use angle brackets, suggesting they were generated separately.

* Lecture Agenda Bugs
** winter2025/lecture7/Agenda.org: && instead of &
Line 23: =(returned >> 8) && 0xFF= should be =(returned >> 8) & 0xFF= in the WEXITSTATUS explanation. =&&= is logical AND (returns 0 or 1), not bitwise AND.

** winter2025/lecture-inf/Agenda.org: broken loop unrolling
Lines 59-65: the "unrolled" loop increments =i= by 1 but accesses =arr[i]= through =arr[i+4]=. Should increment by 5.

** Broken file references (6 total)
- =winter2025/lecture13/Agenda.org= references =lecture9/pipe1.c= (doesn't exist)
- =spring2025/forking/Agenda.org= has 5 references to =lecture9/in-class/= (doesn't exist)
- =spring2025/threading/Agenda.org= references =lecture10/badthreads.c= (doesn't exist)

These all point to a top-level =lecture9/= or =lecture10/= directory from a prior course structure that was reorganized into term-specific directories.

** "IEEE" misspelled as "IEE" (FIXED 2026-07-04)
Was in 5 legacy agendas, then recurred in spring2026 (lecture2 x4, lecture6 x1).
All occurrences fixed with a repo-wide sweep on 2026-07-04. When writing new
agendas: it's "IEEE 754".

** fall2025 lectures 07/08: .long vs .quad inconsistency
Lecture 07 teaches =.quad= as the standard 64-bit directive. Lecture 08 (one week later) uses =.long 400= without explaining the difference. Confusing because C's =long= is 64 bits on Linux x86-64, but gas =.long= is always 32 bits.

* New Term Checklist
When preparing materials for a new term:
1. [ ] Default to =.quad= and scale 8 for assembly data examples
2. [ ] Use =movzbl= instead of =movb= when the full register will be used later
3. [ ] =push=/=pop= callee-saved registers (=%rbx=, =%rbp=, =%r12-r15=) in library functions
4. [ ] Use fd=1 for write syscalls, fd=0 for read syscalls
5. [ ] Use =<>= for system includes, not =""=
6. [ ] Check =fork()= return for =-1= in all non-trivial examples
7. [ ] Call =wait()=/=waitpid()= in examples that fork (or comment why not)
8. [ ] Use =socklen_t= for =accept()= address length parameter
9. [ ] Don't share global buffers across threads in server examples
10. [ ] =malloc= a copy of the fd before passing to =pthread_create=
11. [ ] 4th syscall argument goes in =%r10=, not =%rcx=
