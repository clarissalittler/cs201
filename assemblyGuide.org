* Goals of this document
What you're reading are my supplementary notes on how to write x86-64 assembly, with an eye towards writing complete programs so you can finish your assignments!
* Introduction to assembly
** What is assembly?
When we say "assembly" we're often being a little sloppy. What a processor actually runs is /its instruction set/. The instruction set is just a sequence of bytes that tells the processor, the literal physical hardware that processes high and low voltages, what operations to execute. I cannot stress enough that the instruction set is a /physical/ thing implemented in /physical/ hardware. 

There are a few different standards of instruction set: risc-v is one, arm is a whole family of instruction sets and processor designs, and x86-64 is the one we'll be learning about in this class. Despite the name, x86-64 is used in both Intel and AMD manufactured chips.

When we say "assembly", though, what we're actually talking about are the human-readable/writable depictions of the instruction set that we can actually understand. There has to be a /separate/ program, the assembler, that actually turns this "high-level"[fn:1] language and turns it into the sequence of bytes the processor can actually read.

Different assemblers allow for different syntaxes for writing assembly and have different features, some of which are far more convenient than others.

In this class, we're specifically going to use the gnu assembler, written as =as= on the command line, which uses a particular style of syntax called "AT&T" syntax. Now, AT&T syntax is a little weird and is easy to mess up, but it's also what oldschool linux/unix tools are based on and is the syntax you might be expected to know in future classes. So that constrains our curriculum a bit. 
** Why learn it?
Okay, an obvious question is "why bother learning assembly?". I mean, we have compilers, right? What's the actual thing that it does for us?

So my argument is that
 - it's good to understand the guts of how things work
 - when you need to read assembly you /really/ need it
 - it's helpful in areas of computer science like:
   - compiler writing
   - high performance computing
   - reverse engineering (the act of taking a binary and figuring out what it does)
   - operating system research and development 
** Registers: what are they and why do we need them?
 So we're going to spend a lot of time talking about /registers/. All processors have some form of registers. These are the most low-level storage space, which act basically like "scratch paper" for the processor: a place where computations are done quickly and results are thrown away when no longer needed. Memory is /slow/, and we'll talk more about why later in the course, but the reality is that a register can be accessed in a fraction of a nanosecond while a trip all the way out to main memory can take hundreds of nanoseconds — easily 100x slower. So you need to use registers as much as possible. In fact, while some instructions let you load or save data directly to memory you generally can't load from a location in memory, do an operation, then save to a location in memory as a single step. You have to use at least one register as an intermediary storage space, a kind of workspace, before finalizing your work. So while having more registers would be good, the problem, though, is that each register complicates the physical hardware of the chip.

 For example, on x86-64 systems, you have /16/ (ordinary) registers[fn:2]. Each of which can hold 64 bits (8 bytes) of data. That's not much!

 It's even worse when you consider that the registers aren't "per program running" they're per processor (well, really, per /core/ which you can think of as one of a number of sub-processors that share circuitry with each other), so whenever your computer switches which programs are running at a given moment that program is competing for using those registers.
** By convention
A theme you'll read in this extended tutorial is that a lot of things are "by convention". The problem is that outside of the /physical/ limitations of how instructions are implemented in the hardware, you can kinda do anything with assembly. That doesn't mean you, y'know, /should/. Especially if you want your code to be interoperable with other people's work! If you were to write your own operating system with all its own libraries and its own separate ecosystem, you could potentially buck a bunch of these conventions.

But most of the time you're not going to do that, right? You're going to need to use code other people wrote. Which means that your code needs to abide by certain standards of how to use registers and memory.

Now that being said, usually when you're using a language with a compiler you literally never have to think about any of this because that's what the compiler writers did for you! They generated the correct assembly from your program!

But in this chunk of the course you're going to be /writing/ assembly, which means that you do need to learn some of these conventions.
* Register reference
** The 16 general-purpose registers
 + =%rax=: accumulator register (for operations like mul, div, etc.)
 + =%rbx=: base register (historically used for array base address)
 + =%rcx=: counter register (used in loops and rep instructions)
 + =%rdx=: data register (used in I/O operations, multiplication, and division)
 + =%rsi=: source index for string operations
 + =%rdi=: destination index for string operations
 + =%rbp=: base pointer (often used to point to function stack frames)
 + =%rsp=: stack pointer (points to top of the stack)
 + =%r8= – =%r15=: additional general-purpose registers
 + =%rip= (special case, you won't use it except in rip-relative addressing)

For the calling convention (which registers hold arguments, which are caller-/callee-saved, etc.), see the *Full calling convention reference* section near the end of this document. For floating-point and vector/SIMD registers, see the reference section at the very end.

** Sub-register sizes
 Each of those 64-bit registers has smaller "views" into its lower bits. So when you want to work with just 32, 16, or 8 bits of data, you use a different name for the same register. This matters because instructions often care about operand size (e.g. =movb= works on bytes, =movq= works on quads), and you'll see compiler output using the smaller names all the time.

 For the "legacy" registers (=rax=, =rbx=, =rcx=, =rdx=), the naming goes:

 | 64-bit (quad) | 32-bit (long) | 16-bit (word) | lower 8-bit (byte) |
 |---------------+---------------+---------------+--------------------|
 | =%rax=        | =%eax=        | =%ax=         | =%al=              |
 | =%rbx=        | =%ebx=        | =%bx=         | =%bl=              |
 | =%rcx=        | =%ecx=        | =%cx=         | =%cl=              |
 | =%rdx=        | =%edx=        | =%dx=         | =%dl=              |

 For =%rsi=, =%rdi=, =%rbp=, =%rsp=, the pattern is slightly different:

 | 64-bit | 32-bit  | 16-bit | 8-bit   |
 |--------+---------+--------+---------|
 | =%rsi= | =%esi=  | =%si=  | =%sil=  |
 | =%rdi= | =%edi=  | =%di=  | =%dil=  |
 | =%rbp= | =%ebp=  | =%bp=  | =%bpl=  |
 | =%rsp= | =%esp=  | =%sp=  | =%spl=  |

 And for the newer =%r8= – =%r15=, you just add a suffix:

 | 64-bit | 32-bit  | 16-bit  | 8-bit   |
 |--------+---------+---------+---------|
 | =%r8=  | =%r8d=  | =%r8w=  | =%r8b=  |
 | =%r9=  | =%r9d=  | =%r9w=  | =%r9b=  |

 And so on for =%r10= – =%r15=.

 *Important gotcha:* when you write to a 32-bit register (e.g. =movl $5, %eax=), the CPU /automatically zeros out/ the upper 32 bits of the full 64-bit register. But when you write to an 8-bit or 16-bit register, the upper bits are left alone. That's why you'll often see =movzbl= ("move with zero-extend byte to long") when loading a single byte into a register — it forces the upper bits to zero so you don't get garbage from whatever was there before.

* Sections
 + =.text= is the section you declare for your code
 + =.data= for initialized data you want to modify (global variables)
 + =.rodata= for initialized data you don't want to modify (global constants)
 + =.bss= for uninitialized data that will be zeroed when your program starts

A couple of spellings you'll see that mean the same thing:
 + =.text= and =.section .text= are equivalent. Same for =.data=, =.rodata=, =.bss=.
 + =.global= and =.globl= are aliases. The =.globl= spelling is older and more common in the wild.

I use both forms throughout this guide so you'll recognize them in other people's code, but feel free to pick whichever you prefer for your own programs.

* Data directives
When you put data in =.data=, =.rodata=, or =.bss=, you use /directives/ to tell the assembler what kind of data and how many bytes to emit.

| Directive | Size     | Use for                                                   |
|-----------+----------+-----------------------------------------------------------|
| =.byte=   | 1 byte   | characters, small integers, booleans                      |
| =.word=   | 2 bytes  | 16-bit integers                                           |
| =.long=   | 4 bytes  | 32-bit integers                                           |
| =.quad=   | 8 bytes  | 64-bit integers (= one register-sized value!)             |
| =.ascii=  | varies   | string, /no/ null terminator                              |
| =.asciz=  | varies   | string, automatically null-terminated                     |
| =.skip N= | N bytes  | reserve N uninitialized (or zero-filled in .bss) bytes    |
| =.zero N= | N bytes  | same as =.skip=, both emit N zero bytes                   |

*A warning worth reading twice:* =.long= is *32 bits*, not 64. This trips people up constantly. If you're putting an integer into the =.data= section and you want to load it into a 64-bit register with =movq=, you almost certainly want =.quad=, not =.long=. Using =.long= means you've reserved only 4 bytes, and =movq= will happily read the next 4 bytes (probably some other variable!) along with it.

Examples:
#+begin_src asm
  .section .data
  counter:   .quad 0               # 64-bit counter, starts at 0
  numbers:   .quad 10, 20, 30, 40  # array of four 64-bit ints
  flags:     .byte 1, 0, 1, 1      # four bytes
  name:      .asciz "Clarissa"     # 9 bytes: 8 chars + null terminator
  greeting:  .ascii "hi"           # 2 bytes, no null

  .section .bss
  inputBuf:  .skip 256             # 256 uninitialized bytes
#+end_src

* Addressing modes
Whenever you see parentheses in an operand, you're dereferencing memory. The fully general form of an x86-64 memory operand is:

#+begin_example
disp(base, index, scale)
#+end_example

which the CPU evaluates as:

#+begin_example
address = base + (index × scale) + disp
#+end_example

where:
+ =base= is a register (or omitted)
+ =index= is a register (or omitted)
+ =scale= is =1=, =2=, =4=, or =8= (or omitted — defaults to 1)
+ =disp= is a constant offset (or omitted — defaults to 0)

You almost never use all four parts at once. Here are the patterns you'll actually see:

| Example            | Meaning                          | Typical use                               |
|--------------------+----------------------------------+-------------------------------------------|
| =(%rax)=           | value at the address in =%rax=   | dereference a pointer                     |
| =8(%rax)=          | value at =%rax + 8=              | access a struct field                     |
| =-16(%rbp)=        | value at =%rbp - 16=             | access a local variable                   |
| =(%rbx, %rcx, 8)=  | value at =%rbx + %rcx * 8=       | =arr[i]= where each element is 8 bytes    |
| =num(%rip)=        | value at =num + %rip-offset=     | access a global via RIP-relative          |

One important thing to keep in your back pocket: =lea= uses the exact same syntax but /doesn't dereference/. It just computes the address and puts it in the destination. So =lea 8(%rbx, %rcx, 4), %rax= gives you =%rax = %rbx + %rcx*4 + 8=, not the value at that address. That's why =lea= sneaks into code as a cheap arithmetic instruction — you can compute =base + index * scale + disp= in one instruction without ever touching memory.

* Example programs
** A first program
This is a simple program that exits with a status of -1 when you run it. You can check the exit code of the program with =echo $?= at the command line. Now here's something that trips people up: you'll actually see 255, not -1. That's because exit codes are unsigned bytes (0-255), and -1 in two's complement is 0xFF, which is 255.

#+begin_src asm

          .text           # Indicates the start of the code section
          .global _start  # Declares the entry point of the program for the linker

  _start:         # Program entry point
          mov $60,%rax    # Move the syscall number for exit (60) into the rax register
                          # On Linux x86_64, syscall 60 is the exit system call
        
          mov $-1,%rdi    # Move the exit status code (-1) into the rdi register
                          # -1 typically indicates an error or unsuccessful termination
        
          syscall         # Invoke the system call
                          # This will immediately terminate the program with the specified exit status

#+end_src

If you /don't/ properly exit the program you'll see a segfault as the program attempts to move to executing the next region of memory after the last instruction as though /it/ is an instruction.
** How to actually compile and run this
Okay, before we go any further — how do you actually turn that text file into a running program? There are two steps: /assembling/ (turning your =.s= file into an object file of machine code) and /linking/ (stitching that object file together into a real executable).

Save the program above as =first.s= and then run:
#+begin_example
as first.s -o first.o        # assemble into an object file
ld first.o -o first          # link into an executable
./first                      # run it
echo $?                      # check the exit code (will print 255, see above)
#+end_example

That's it. If you're getting linker errors about "undefined reference to =_start=", double-check that you wrote =.global _start= (or =.globl _start=, they're the same thing — more on that later) and that your label is spelled exactly =_start=, with the underscore.

If you want to debug your program, compile with extra info:
#+begin_example
as -g first.s -o first.o
ld first.o -o first
gdb ./first
#+end_example

There's a whole section on gdb later in this guide once we have more interesting programs to poke at.
** Basic arithmetic and registers
 Basic arithmetic is done with the =add= and =sub= instructions. Note that, like most binary operations in assembly, they take only two arguments and store the result of the operation in the second argument
#+begin_src asm
          .text
          .global _start

          ## q - quad sized (64 bits)
          ## l - long (32 bits)
          ## w - word sized (16 bits)
          ## b - byte (8 bits)
          ##  add/sub source arg,destination arg
          ## source can be a value or a register (or a memory location)
          ## destination has to be a register (or memory location)
  _start:
          mov $1,%rax
          mov $2,%rdx
          sub %rax,%rdx           # sub s,d -> d = d - s 
          mov %rdx,%rdi           # we stored our computation in rdx BUT the syscall to exit needs the exit code value passed in via rdi (by The Calling Convention)

          mov $60,%rax
          syscall
#+end_src
** cmp and jmp
Now assembly doesn't have if-statements like you're used to. Instead you have to do a =cmp= instruction and then different kinds of /jump/ based on the result of the =cmp=. Jumps need to take an address of where to go next, generally in the form of a label. You can make labels by just writing a name and then a =:=.

We can summarize this in the following table where we assume that we've just done =cmp a,b= (I always double-check this table when I need it, and you should too). These are the /signed/ conditional jumps — there are unsigned variants (=jb=, =ja=, =jbe=, =jae=) that you should use when comparing unsigned values, like loop indices against a length; see the Common Gotchas section.

| Instruction | When it jumps                        |
|-------------+--------------------------------------|
| =jmp=       | always (unconditional)               |
| =jl=        | b < a                                |
| =jle=       | b <= a                               |
| =je=        | a == b                               |
| =jne=       | a != b                               |
| =jg=        | b > a                                |
| =jge=       | b >= a                               |


#+begin_src asm
  .text                   # Indicates the start of the code section
  .global _start          # Makes the _start label visible to the linker

  _start:
          # Load some initial values into registers
          mov $1,%rax     # Store the value 1 in the rax register
          mov $2,%rbx     # Store the value 2 in the rbx register

          # Compare the values in rax and rbx
          cmp %rbx,%rax   # Compare rax to rbx 
                          # Note: cmp %rbx,%rax does rax - rbx internally
                          # Flags are set based on this subtraction

          # Conditional jump based on the comparison
          jne notEqual    # Jump to 'notEqual' label if NOT equal
                          # This means the jump happens if rax != rbx

          # If values are equal, set exit code to -1
          mov $-1,%rdi    # Load -1 as the exit status
          jmp finish      # Unconditionally jump to finish

  notEqual:
          # If values are not equal, set exit code to 10
          mov $10,%rdi    # Load 10 as the exit status

  finish:
          # Syscall to exit the program
          mov $60,%rax    # System call number for exit
          syscall         # Invoke the system call
#+end_src

*** Anonymous labels
A feature I didn't even learn myself until recently is that you can re-use label names by giving a /number/ in the label and then referring to it with a direction:

Writing a digit followed by =f= (e.g. =1f=) means jump forward to the next label with that number, and a digit followed by =b= (e.g. =1b=) means jump backward to the previous one. So you can sprinkle =1:= labels throughout your code and use =jmp 1f= / =jmp 1b= to hop between them. Try changing the fs and bs in the following code to break it in different ways.

[please note this example uses concepts that are explained elsewhere in the document]
#+begin_src asm
  # Read-only data section (constants)
  .section .rodata
      # Define first message string (null-terminated)
      msg1:   .asciz "In the first sublabel\n"
      # Calculate length of first message
      msg1len = . - msg1

      # Define second message string (null-terminated)
      msg2:   .asciz "In the second sublabel\n"
      # Calculate length of second message
      msg2len = . - msg2

  # Executable code section
  .section .text
      # Make _start symbol globally accessible (entry point)
      .globl _start

  # Program entry point
  _start:
      # Call functions in order: biglabel2 first, then biglabel1
      call biglabel2
      call biglabel1
    
      # Exit program gracefully
  1:  
      # syscall for program exit
      # rax = 60 (exit syscall)
      # rdi = 0 (exit status code)
      mov $60,%rax
      xor %rdi,%rdi
      syscall
    
  # First function: print first message
  biglabel1:
      # Local jump to next instruction (obviously for toy purposes)
      jmp 1f
  1:
      # Prepare arguments for write syscall
      # rsi = message address (using RIP-relative addressing)
      # rdx = message length
      # rax = syscall number for write (1)
      # rdi = file descriptor (1 = standard output)
      lea msg1(%rip),%rsi
      mov $msg1len,%rdx
      mov $1,%rax
      mov $1,%rdi
      syscall
      ret

  # Second function: print second message
  biglabel2:
      # Local jump to next instruction (obviously for toy purposes)
      jmp 1f
  1:
      # Same syscall setup as biglabel1, but with second message
      lea msg2(%rip),%rsi
      mov $msg2len,%rdx
      mov $1,%rax
      mov $1,%rdi
      syscall
      ret


#+end_src

** Using global variables
 We can make global variables by putting them in the =.data= section of the program. We access those variables with rip-relative addressing!

 Now this requires a bit of explaining:
 + =%rip= holds the address of the next instruction to be executed
 + labels you define in your data sections are mapped to actual addresses in the program as its loaded into memory
 + but these addresses, if you're making "position independent executables", aren't known at compile or even link time
 + so instead you can do "rip relative addressing", where you tell the linker to calculate the distance in memory between the label and where you are in the program when you're using the label
 + the executable is built with that /offset/ in mind and uses *that* to find the data in memory because the one thing your executable does know at all times is what the instruction pointer (rip) is pointing to!

Here are some examples of how this looks:

#+begin_src asm
  # Data section: Declares initialized static data
          .section .data
  num1:   .quad 200    # Declares a 64-bit integer variable named 'num1' with initial value 200

  # Code section begins

          .section .text
          .global _start       # Makes the _start label visible to the linker

  _start:
          # Load the value of num1 into %rbx
          # RIP-relative addressing is used to get the memory location of num1
          mov num1(%rip),%rbx

          # Add 10 to the value stored in %rbx
          add $10,%rbx          # %rbx now holds 210

          # Prepare arguments for system exit
          # Move our computed result into %rdi (first argument for exit syscall)
          mov %rbx,%rdi

          # Set up syscall for program exit
          mov $60,%rax            # 60 is the syscall number for exit
          syscall                 # Invoke the system call to exit the program
#+end_src


And here's a version that uses the "load-effective address" instruction with explicit dereferencing
#+begin_src asm
  # Data section: Declares initialized static data
          .section .data
  num1:   .quad 200    # Declares a 64-bit integer variable named 'num1' with initial value 200

  # Code section begins

          .section .text
          .global _start       # Makes the _start label visible to the linker

  _start:
          # Load the address of num1 into %rbx
          # RIP-relative addressing is used to get the memory location of num1
          lea num1(%rip),%rbx          # Put the address of num1 into the %rbx register

          # Add 10 to the value stored at the memory location pointed to by %rbx
          # The parentheses () mean "value at this memory address"
          addq $10,(%rbx)         # Adds 10 to the current value of num1

          # Prepare arguments for system exit
          # Move the new value of num1 into %rdi (first argument for exit syscall)
          mov num1(%rip),%rdi

          # Set up syscall for program exit
          mov $60,%rax            # 60 is the syscall number for exit
          syscall                 # Invoke the system call to exit the program
#+end_src



and here's how you'd make an array of ints and sum all of their elements. Please note the description of how to use the =lea= (load effective address) instruction. This instruction is basically how you do pointer arithmetic in assembly!
#+begin_src asm
  ### A brief intro to lea (Load Effective Address):
  ### 
  ### Basic syntax: lea source, destination
  ###
  ### 1. Simple address loading:
  ###    lea arr(%rip), %rax   # Loads the memory address of 'arr' into %rax
  ###
  ### 2. Convenient way to do arithmetic
  ###    lea (%rbx, %rcx, 4), %rax   # Calculates: %rbx + (%rcx * 4)
  ###
  ### 3. Complex address calculations:
  ###    lea 8(%rbx, %rcx, 4), %rax  -> %rax = %rbx + (%rcx * 4) + 8 (doesn't dereference!)
  ###    lea (%rbx, %rcx, 8), %rax   -> %rax = %rbx + (%rcx * 8) (doesn't dereference!)

          .section .data
  arr1:   .quad 1,2,3,4     # Define an array of 4 integers (64-bit each)

          .section .text
          .global _start

  _start:
          # Load the base address of the array into %rbx
          # %rip-relative addressing ensures position-independent code
          lea arr1(%rip),%rbx

          # Initialize loop counter (i) to 0
          mov $0,%rcx

          # Initialize sum to 0
          mov $0,%rax

  loopBody:
          # Compare loop counter to array length (4)
          cmp $4,%rcx

          # If i >= 4, exit loop
          jge done

          # Add current array element to sum
          # (%rbx,%rcx,8) calculates the address of arr1[i]
          # 8 is the size of each quad (64-bit) element
          add (%rbx,%rcx,8),%rax  

          # Increment loop counter
          add $1,%rcx             

          # Jump back to beginning of loop
          jmp loopBody
        
  done:
          # Move sum to %rdi (first argument for exit syscall)
          mov %rax,%rdi

          # Syscall number for exit
          mov $60,%rax

          # Invoke system call to exit program
          syscall
#+end_src

and here's a slight variation that explicitly loads the address into a register and then dereferences it directly:
#+begin_src asm
      # Data section: where we define our static data
      .section .data
      # Define an array of 4 integers (64-bit each)
      arr1:   .quad 1,2,3,4

      # Code section where our program instructions live
      .section .text
      .global _start  # Entry point of the program

  _start:
      # Load the memory address of arr1 into %rbx
      # %rip is the instruction pointer, used for position-independent code
      lea arr1(%rip),%rbx     # %rbx now contains the base address of arr1

      # Initialize loop counter (i) to 0
      mov $0,%rcx             # %rcx will be our loop counter (i)

      # Initialize sum to 0
      mov $0,%rax             # %rax will store our running sum

  loopBody:
      # Compare loop counter to array length
      # If i >= 4, we're done looping
      cmp $4,%rcx             # Compare %rcx (i) with 4
      jge done                # Jump to 'done' if i >= 4

      # Calculate address of current array element
      # lea calculates address without actually loading the value
      # (%rbx,%rcx,8) means: base address + (index * 8-byte element size)
      lea (%rbx,%rcx,8),%rdx  # %rdx now points to current array element

      # Add current array element to sum
      # (%rdx) dereferences the pointer, getting the actual value
      add (%rdx),%rax         # sum += arr1[i]

      # Increment loop counter
      add $1,%rcx             # i++

      # Jump back to start of loop
      jmp loopBody
        
  done:
      # Prepare to exit program
      # Put sum in %rdi (first argument for exit syscall)
      mov %rax,%rdi

      # Set up exit syscall (60 is exit)
      mov $60,%rax
      syscall  # Invoke system call to exit

#+end_src
** Reading and writing from the terminal!
Now we get to how to read or write text from the terminal. We need to use the underlying read and write system calls and we're going to have to use actual /buffers/ of bytes we've set aside.

First is our "hello world", that we're finally getting to:
#+begin_src asm
          .section .rodata           # Read-only data section (constant data)
  msg:    .asciz "Hello world!\n"   # Define a null-terminated string
  hellolen = . - msg         # Calculate length of the string by subtracting start address from current address

          .section .text     # Code section begins
          .globl _start      # Make _start symbol globally visible for linker

  _start:
          ## call the write syscall
          ## and exit appropriately
          mov $1,%rax        # Set %rax to 1 (syscall number for write)
          mov $1,%rdi        # File descriptor: 1 is stdout (2 would be stderr)
          lea msg(%rip),%rsi # Load effective address of message relative to instruction pointer
          mov $hellolen,%rdx # Move message length into %rdx (third argument for write)

          syscall            # Invoke system call to print message

          xor %rdi,%rdi      # Zero out %rdi (sets exit status to 0)
          mov $60,%rax       # Set %rax to 60 (syscall number for exit)
          syscall            # Invoke system call to exit program

#+end_src

We don't strictly need to have null-terminated strings here because read and write don't actually care about this: they're too low-level! But it's a good habit to be in. Note that, much like how the variable for a buffer in C is pointing to the start of the buffer, see that when we pass the buffer to a function we're just passing the address to the start of the buffer!

Neat, right?

Now here's an echo program that reads in a string and writes it back out again:
#+begin_src asm
  # This is a simple program that reads input from stdin and then writes it back out

          .section .bss           # Uninitialized data section
  buff:   .skip 128       # Allocate 128 bytes of buffer space for reading input

          .section .text  # Code section
          .globl _start   # Makes the entry point visible to the linker

  _start:
          ## Reading input from stdin
          mov $0,%rax             # System call number for read (0)
          mov $0,%rdi             # File descriptor for stdin (standard input)
          lea buff(%rip),%rsi     # Load effective address of buffer into source index
          mov $128,%rdx           # Maximum number of bytes to read (buffer size)
          syscall                 # Invoke the system call to read input

          ## Writing the input back out
          ## Note: %rax now contains the number of bytes actually read
          mov %rax,%rdx           # Move the byte count to the length parameter
          mov $1,%rax             # System call number for write (1)
          lea buff(%rip),%rsi     # Point to the same buffer we read into
          mov $1,%rdi             # File descriptor for stdout (standard output)
          syscall                 # Invoke the system call to write output

          ## Exit the program cleanly
          xor %rdi,%rdi           # Zero out exit code (0 means successful exit)
          mov $60,%rax            # System call number for exit
          syscall                 # Terminate the program
#+end_src

Nice and simple! Now you might notice we used =.skip 128= to allocate the buffer. In GNU as, =.skip N= and =.zero N= are actually equivalent: both emit N zero bytes. The =.bss= section is special, though, in that the OS guarantees it'll be zeroed out when your program starts, so either directive works fine here.

*** Function examples
As summarized above, functions are really just labels that we jump to with specific /calling conventions/ that give us an ordered way to pass arguments into functions, establish scope for local variables, and then make sure to set things up correctly in case we call /other/ functions inside our functions

          ##   - Second number in %rsi (second argument)
          ## Output:

*** What is the stack?
Okay, so we need to spend a bit of time talking about the /stack/ in program execution. You've probably already heard of the stack before: it's where data you allocate that doesn't go on the *heap*, but we haven't yet explained why we call the stack, /a stack/.

A "stack" in the computer science sense is a last-in-first-out data structure. Think of a stack of plates in a cafeteria: you can only add plates to the top and take plates off the top. The two operations are =push= (put something on top) and =pop= (take the top thing off).

The program stack works exactly like this. It's a region of memory, and the register =%rsp= (the "stack pointer") always points to the "top" of the stack. Now here's the part that trips people up: the stack grows /downward/, from high memory addresses to low memory addresses. So "pushing" something onto the stack actually /decreases/ =%rsp=. I know that's confusing, but it's just a convention baked into how x86 works and you'll have to live with it.

Concretely, when you write =push %rax=, the processor:
1. Subtracts 8 from =%rsp= (making room for 8 bytes)
2. Stores the value of =%rax= at the new address in =%rsp=

And =pop %rax= does the reverse:
1. Loads the value at the address in =%rsp= into =%rax=
2. Adds 8 to =%rsp= (reclaiming the space)

So why do we need this for functions? Well, when you =call= a function, the processor automatically pushes the /return address/ (where to jump back to when the function is done) onto the stack. When the function executes =ret=, it pops that address and jumps back to it. Inside the function you might also need to save some registers and make room for local variables, and the stack gives you a nice orderly way to do all of that.

The base pointer =%rbp= is used as a fixed reference point within a function's "stack frame" (the chunk of stack belonging to that particular function call). While =%rsp= moves around as you push and pop things, =%rbp= stays put for the duration of the function, so you can always find your local variables at fixed offsets like =-8(%rbp)= or =-16(%rbp)=.

*** Stack alignment
One more thing before we look at the example: the System V ABI (the calling-convention spec everyone on Linux agrees to follow) says that =%rsp= must be /16-byte aligned/ right before any =call= instruction. That is, =%rsp % 16 == 0= at the moment you execute =call=.

Why? Because some instructions, especially the SSE/AVX ones, require their memory operands to be 16-byte aligned. Functions are allowed to assume the stack is aligned when they start, and things go sideways (usually a segfault inside printf or similar) if that assumption is violated.

Let's trace how alignment works:
+ Right before you execute =call=, =%rsp= must be 16-byte aligned.
+ The =call= instruction pushes the return address (8 bytes), so on entry to your function =%rsp % 16 == 8=.
+ =push %rbp= pushes 8 more bytes, bringing =%rsp % 16 == 0= again.
+ If you then =sub $N, %rsp= for local variables, *N should be a multiple of 16* to keep alignment.

This is why you keep seeing =sub $16, %rsp= or =sub $32, %rsp= in the examples — even if you only need 8 bytes of locals, you round up to 16. If you need to push things in addition to the prologue and then make a =call=, you need to account for that too (e.g. push an extra 8 to compensate, or save the value in a local stack slot instead).

*A common subtle bug:* pushing and popping registers across a =call= inside a function is the classic way to misalign the stack. After the prologue (=push %rbp / mov %rsp, %rbp / sub $16, %rsp=), =%rsp= is aligned. If you then do =push %rdi= to save an argument across a recursive call, =%rsp= is now off by 8, and the recursive call enters misaligned. The safe pattern is to save the value in a local slot (=mov %rdi, -16(%rbp)=) instead of pushing it.

*What about =_start=?* At process entry, the kernel hands you =%rsp= already 16-byte aligned (=%rsp % 16 == 0=) — as if you were a caller about to make a =call=. So if you =call= a function directly from =_start= without having pushed anything first, the =call= itself pushes 8 bytes and the callee starts with =%rsp % 16 == 8=, exactly what it expects. You only get in trouble if you push an odd number of 8-byte values before the first =call=.

Now we're ready to demonstrate how to properly handle the stack!
#+begin_src asm
          .text                   # Start of the code section
          .global _start          # Make _start symbol globally visible for the linker

  ## This is a function that demonstrates:
  ## 1. Using local variables on the stack
  ## 2. Function call conventions
  ## 3. Basic arithmetic operations
  ## long fun(long a, long b){
  ##   long c = a + b;
  ##   long d = 2+b;
  ##   return (c + d);
  fun:    
          # Standard function prologue
          # Save the old base pointer (frame pointer)
          push %rbp
        
          # Set up new base pointer for this stack frame
          mov %rsp,%rbp
        
          # Allocate 16 bytes of local stack space
          # This creates space for two 8-byte (64-bit) local variables
          sub $16,%rsp

          # First parameter (a) is in %rdi
          # First local variable will be at -8(%rbp)
          # Compute a + b and store at -8(%rbp)
          mov %rdi,-8(%rbp)
          add %rsi,-8(%rbp)

          # Second local variable at -16(%rbp)
          # Compute b + 2 and store at -16(%rbp)
          mov %rsi,-16(%rbp)
          addq $2,-16(%rbp)

          # Prepare return value by:
          # 1. Load second local var into %rax
          # 2. Add first local var to %rax
          mov -16(%rbp),%rax
          add -8(%rbp),%rax

          # Function epilogue: 
          # 'leave' is a single instruction that does:
          # mov %rbp,%rsp
          # pop %rbp
          leave
          ret
        
  _start:
          # Set up arguments for fun()
          # First arg (3) goes in %rdi
          mov $3,%rdi
          # Second arg (4) goes in %rsi
          mov $4,%rsi

          # Call the fun() function
          call fun

          # Prepare to exit
          # Return value from fun() is already in %rax
          # Move return value to %rdi (exit status)
          mov %rax,%rdi
        
          # Syscall number for exit
          mov $60,%rax
        
          # Invoke system call to exit
          syscall
#+end_src

** readInt, writeInt, and loading in functions
Okay now we're getting to a point where we want to be able to split our code between multiple files.

It turns out this is already pretty simple! Here's a readInt function but note that the exposed symbol isn't =_start= it's =readInt=! That's because this isn't a "main" program, it's a library function we're defining:
#+begin_src asm
      .section .bss                # Begin uninitialized data section (.bss)
  buffer: .zero 128                # Allocate 128 bytes for 'buffer', initialized to zero

      .section .text               # Begin code section (.text)
      .global readInt              # Make 'readInt' function accessible from other files

  # Function: parseInt
  # Description: Parses ASCII digits from the buffer and converts them into an integer.
  # Parameters:
  #   - %rdi: Address of the buffer containing the input string
  #   - %rsi: Number of characters to process
  # Internals:
  #   - %rcx: Index into the buffer (caller sets to 0 before calling)
  #   - %rax: Accumulator for the result (caller clears to 0 before calling)
  # Returns:
  #   - %rax: The resulting integer value
  parseInt:
      movzbl (%rdi,%rcx,1), %r8d   # Load one byte from buffer[%rcx], zero-extended into %r8
      sub $'0', %r8                # Convert ASCII character to its numeric value
      imul $10, %rax               # Multiply accumulator (%rax) by 10 (shifting left in decimal)
      add %r8, %rax                # Add the numeric value of current digit to accumulator
      inc %rcx                     # Increment buffer index (%rcx)
      cmp %rsi, %rcx               # Compare index with total number of characters to process
      jb parseInt                  # If index < total (unsigned), repeat the loop
      ret                          # Return from function with result in %rax

  # Function: readInt
  # Description: Reads input from standard input (stdin), stores it in the buffer,
  #              and then converts the input string into an integer using parseInt.
  # Returns:
  #   - %rax: The integer value read from input
  readInt:
      push %rbx                    # Save callee-saved register
      # Prepare for syscall to read from stdin
      mov $0, %rax                 # Syscall number 0 (sys_read)
      mov $0, %rdi                 # File descriptor 0 (stdin)
      lea buffer(%rip), %rsi       # Load address of 'buffer' into %rsi
      mov $128, %rdx               # Number of bytes to read (up to 128)
      syscall                      # Make the syscall to read input

      mov %rax, %rbx               # Store the number of bytes read in %rbx

      # Initialize registers for parsing
      mov $0, %rcx                 # Set index (%rcx) to 0
      mov $0, %rax                 # Clear accumulator (%rax) for result
      lea buffer(%rip), %rdi       # Load address of 'buffer' into %rdi for parseInt
      dec %rbx                     # Decrement byte count (%rbx) by 1 (to exclude newline)
      mov %rbx, %rsi               # Move byte count to %rsi (number of characters to process)

      call parseInt                # Call parseInt to convert input string to integer
      pop %rbx                     # Restore callee-saved register
      ret                          # Return from readInt with result in %rax
#+end_src

This program might seem a little intimidating but it's not /that bad/ in the end. Basically, we're reading up to 128 characters with a read system call into a buffer of bytes. From *here* go into the parseInt helper function and what it does is start at the left-hand side of the string and interpreting the bytes as numbers (which is accomplished with the Very Clever trick of taking the byte and subtracting =$'0'= (note: that's =$'0'= not =$0=, in other words it's the value of 0 as a character not 0 as a number) to get the actual value of the /number/ from its /ascii/ code.

For every digit you read you need to multiply the number you've read so far by 10 and then add the new amount. We just accumulate that into %rax since that's the register the return value has to be in anyway.

[As a side note, when I originally wrote this program it took me an *hour* in order to discover I'd accidentally typed =$0= and not =$'0'=. So remember that if you feel like you have some goofy debugging stories with assembly]

You can compile this like normal with
#+begin_example
as readInt.s -o readInt.o
#+end_example

but you /can't/ link it into an executable!

We can use it now, though in other functions by importing it with =.extern= and then linking it in. For example, here's a recursive fibonacci calculator!
#+begin_src asm
        
  ### Program: Compute Fibonacci number recursively in assembly
  ### This program reads an integer n from the user,
  ### computes the nth Fibonacci number using recursion,
  ### and exits with the Fibonacci number as the exit code.
  ### The result is not printed to the screen, but returned as the exit code.

      .section .text            # Code section where the instructions are stored
      .global _start            # Define _start as global symbol; entry point of the program
      .extern readInt           # Declare that readInt function is defined externally (provided elsewhere)

  # Define the Fibonacci function
  # Stack frame layout (below %rbp):
  #   -8  : holds fib(n - 1) across the second recursive call
  #   -16 : holds the original n across both recursive calls
  fib:
      # Function prologue - set up the stack frame
      push %rbp                 # Save the base pointer of the previous frame (caller)
      mov %rsp, %rbp            # Set up the base pointer for this function's stack frame
      sub $16, %rsp             # Allocate 16 bytes for local variables (keeps %rsp 16-byte aligned)

      # Check if n <= 1 (base case)
      cmp $1, %rdi              # Compare input n (%rdi) with 1
      jle .base                 # If n <= 1, jump to .base label (base case)

      # Save n in a local slot before modifying %rdi.
      # We *don't* push %rdi here — pushing would make %rsp % 16 == 8, which would
      # misalign the stack for the upcoming recursive call.
      mov %rdi, -16(%rbp)       # save n

      # Recursive case: compute fib(n - 1)
      dec %rdi                  # n - 1
      call fib                  # result in %rax
      mov %rax, -8(%rbp)        # stash fib(n - 1)

      # Compute fib(n - 2)
      mov -16(%rbp), %rdi       # reload n
      dec %rdi
      dec %rdi                  # n - 2
      call fib                  # result in %rax

      # Add fib(n - 1) and fib(n - 2)
      add -8(%rbp), %rax        # %rax = fib(n - 1) + fib(n - 2) = fib(n)

      # Function epilogue - restore the stack frame
      mov %rbp, %rsp            # Restore the stack pointer to the base pointer
      pop %rbp                  # Restore the base pointer of the caller
      ret                       # Return to the caller; result is in %rax

      # Base case: when n <= 1, fib(n) = n
      # (Label starts with '.' so it's a local symbol, won't collide with
      # anything the linker might also define.)
  .base:
      mov %rdi, %rax            # Set return value to n (%rdi)
      mov %rbp, %rsp            # Restore the stack pointer to the base pointer
      pop %rbp                  # Restore the base pointer of the caller
      ret                       # Return to the caller; result is in %rax

  # Entry point of the program
  _start:
      call readInt              # Call external function to read an integer from the user; result in %rax
      mov %rax, %rdi            # Move input value from %rax to %rdi (first argument for fib)

      call fib                  # Call fib(n); result will be in %rax

      # Prepare to exit the program with fib(n) as the exit code
      mov %rax, %rdi            # Move fib(n) result to %rdi (exit code expected in %rdi)
      mov $60, %rax             # System call number for exit (60)
      syscall                   # Make the system call to exit the program
#+end_src

#+end_example

*** A quick detour: =div= and =idiv=
Unlike =add= or =sub=, which take a source and destination, =divq= only takes /one/ operand — the divisor — and implicitly uses the *pair* of registers =%rdx:%rax= as a 128-bit dividend. Yes, 128 bits.

The mechanics:
+ /Before/ =divq <src>=: =%rdx:%rax= holds a 128-bit unsigned integer, where =%rdx= is the high 64 bits and =%rax= is the low 64 bits. =<src>= is the 64-bit divisor.
+ /After/ =divq <src>=: =%rax= holds the quotient, =%rdx= holds the remainder.

So if you want to divide a regular 64-bit number (say, the value in =%rax=) by something, you /must/ zero =%rdx= first, otherwise you'll be dividing some 128-bit garbage and getting garbage out. You'll see =xorq %rdx, %rdx= right before a =divq= basically everywhere.

=idivq= is the signed version. Same register gymnastics, but it treats the values as signed.

This is what's going on in the conversion loop inside =writeInt= below:
#+begin_src asm
  xorq %rdx, %rdx       # zero out the high half so %rdx:%rax = just %rax
  movq $10, %rbx        # divisor
  divq %rbx             # %rax = quotient, %rdx = remainder
#+end_src
That's how you peel off the last decimal digit of a number: divide by 10, and the remainder is the digit. Repeat until the quotient is zero and you've got all the digits (in reverse order).

(Tiny note for =idivq=: if the value in =%rax= might be negative, you need to /sign-extend/ it into =%rdx= instead of zeroing it. The =cqo= instruction does that — it fills =%rdx= with copies of the sign bit of =%rax=. But =writeInt= works with the absolute value, so =xorq %rdx, %rdx= is fine.)

Now, finally, =writeInt=:
#+begin_src asm
          .text
          .global writeInt

      # Function: writeInt
      # -------------------
      # Writes the integer value in %rdi to the standard output.
      #
      # This function converts the integer to its ASCII string representation
      # and outputs it using the sys_write system call.
      #
      # Inputs:
      #   %rdi - The integer to be printed.
      #
      # Clobbers (caller-saved, so no need to preserve):
      #   %rax, %rcx, %rdx, %rsi, %r8
      #
      # Preserves (callee-saved, saved/restored in the prologue/epilogue):
      #   %rbx, %rbp
      #
      # Stack layout (below %rbp):
      #   -32 .. -1   : 32-byte buffer for the string representation
      #   -40         : saved %rbx
      #   -48         : padding (keeps %rsp 16-byte aligned)
      #
      # Notes:
      #   - The function handles negative integers, including INT_MIN (-2^63),
      #     which cannot be negated in two's complement representation.
      #   - The integer is converted to a string by repeatedly dividing by 10
      #     and storing the digits in reverse order in the buffer.

  writeInt:
          # Function prologue: set up the stack frame
          pushq   %rbp                # Save the caller's base pointer on the stack
          movq    %rsp, %rbp          # Set base pointer (%rbp) to current stack pointer (%rsp)
          subq    $48, %rsp           # 32-byte buffer + 8 for saved %rbx + 8 pad (keeps %rsp aligned)
          movq    %rbx, -40(%rbp)     # Save callee-saved %rbx (we use it as the divisor below)

          # Variables:
          # We will use a buffer of 32 bytes on the stack to store the string representation
          # of the integer. The buffer extends from address (%rbp - 32) to (%rbp - 1).
          # We will use %rsi as a pointer to the current position in the buffer.

          # Initialize buffer pointer to the end of the buffer (start filling from the end)
          leaq    -1(%rbp), %rsi      # Load effective address (%rbp - 1) into %rsi
                                      # %rsi now points to the last byte of the buffer
          movq    $0, %rcx            # Initialize digit count to 0
          movq    %rdi, %rax          # Move the input integer from %rdi to %rax for processing
          movq    $0, %r8             # Initialize negative flag in %r8 to 0 (0 means positive)

          # Handle the special case when the input integer is zero
          cmpq    $0, %rax            # Compare %rax with zero
          jne     check_negative      # If %rax is not zero, skip to check_negative
          # If %rax is zero:
          movb    $'0', (%rsi)        # Store ASCII character '0' into the buffer at (%rsi)
          movq    $1, %rcx            # Set digit count to 1
          jmp     write_output        # Jump to write_output to print the character

  check_negative:
          # Check if the number is negative
          testq   %rax, %rax          # Test %rax; sets flags based on the value
          jge     convert_number      # If %rax >= 0, skip to convert_number
          # If the number is negative:
          movq    $1, %r8             # Set negative flag (%r8) to 1
          negq    %rax                # Negate %rax to get the absolute value
          jno     convert_number      # If no overflow, proceed to convert_number
          # Handle INT_MIN (-2^63), which cannot be negated
          # Note: we need movabsq here, not movq — the value 2^63 doesn't fit
          # in a 32-bit sign-extended immediate, so a plain movq won't encode it.
          movabsq $9223372036854775808, %rax  # Set %rax to 2^63 (absolute value of INT_MIN)

  convert_number:
          # Convert the integer to its string representation
  convert_loop:
          xorq    %rdx, %rdx          # Clear %rdx (set to zero) before division
          movq    $10, %rbx           # Load divisor 10 into %rbx
          divq    %rbx                # Unsigned divide %rdx:%rax by %rbx
                                      # After division:
                                      # - %rax: quotient
                                      # - %rdx: remainder
          addb    $'0', %dl           # Convert remainder to ASCII character
          subq    $1, %rsi            # Move back one byte in the buffer
          movb    %dl, (%rsi)         # Store character in buffer at (%rsi)
          incq    %rcx                # Increment digit count
          cmpq    $0, %rax            # Compare quotient %rax with zero
          jne     convert_loop        # If quotient is not zero, repeat loop

          # Add negative sign if necessary
          cmpq    $0, %r8             # Check negative flag (%r8)
          je      write_output        # If number is positive, skip to write_output
          subq    $1, %rsi            # Move back one byte for '-'
          movb    $'-', (%rsi)        # Store '-' in buffer at (%rsi)
          incq    %rcx                # Increment digit count

  write_output:
          # Prepare for sys_write system call
          # sys_write arguments:
          #   %rax - syscall number (1)
          #   %rdi - file descriptor (1 for stdout)
          #   %rsi - pointer to buffer (already set)
          #   %rdx - number of bytes to write
          movq    $1, %rax            # Syscall number for sys_write
          movq    $1, %rdi            # File descriptor for stdout
          # %rsi already points to the start of the string
          movq    %rcx, %rdx          # Set %rdx to digit count (number of bytes)
          syscall                     # Make the system call

          # Function epilogue: restore callee-saved register and stack frame
          movq    -40(%rbp), %rbx     # Restore %rbx before we tear down the frame
          leave                       # Restore stack frame (movq %rbp, %rsp; popq %rbp)
          ret                         # Return from the function

#+end_src

You can include this just like the =readInt= function by putting the integer you want to print in =%rdi=. This code is fun because it allocates a buffer on the stack locally!

* Debugging with gdb
Assembly is the language where you most need a debugger, and luckily =gdb= is perfectly happy to step through it with you. You just have to teach yourself a few commands.

First, compile with debug info:

#+end_example

| =break fib=         | Set a breakpoint at a label                                             |

A few tips that took me embarrassingly long to learn:

+ The TUI layouts (=layout asm=, =layout regs=) can get visually glitchy; =Ctrl-L= redraws the screen.
+ If you want to inspect the stack after a crash, =info frame= tells you where you are and =backtrace= shows you how you got there (though the backtrace may be fuzzy in hand-rolled assembly because gdb is guessing at frame layout).
+ =tui disable= gets you back to plain-text gdb if the split-pane view is annoying you.
+ You can pass input to the program you're debugging via =run < input.txt=.
+ If your program loops forever, =Ctrl-C= in gdb interrupts it and drops you back at the prompt.

The single most useful habit is: when you're confused about what a piece of code is doing, step through it instruction-by-instruction with =si= and watch the registers change. Ninety percent of assembly bugs become obvious when you actually see the values.

* Common gotchas
These are the bugs I've seen students hit every single term. If something is mysteriously wrong with your assembly program, check this list first.

** =.long= where you meant =.quad=
This is *by far* the most common assembly bug. =.long= is 4 bytes (32 bits), not 8. If you write:
#+begin_src asm
  .section .data
  myNum: .long 42           # only 4 bytes!

  .section .text
  mov myNum(%rip), %rax     # reads 8 bytes — 4 of yours + 4 of whatever comes next
#+end_src
then =%rax= gets your 42 in the low 4 bytes and *whatever is sitting in the next 4 bytes of memory* in the high bytes. If you want 64-bit integers, use =.quad=.

** Loading a byte without zero-extending
If you do =movb (%rsi), %al=, the upper 56 bits of =%rax= are left alone — so if =%rax= had garbage in it, you'll interpret that garbage as part of your value. Use =movzbl= ("move, zero-extend, byte to long") or =movzbq= to force the upper bits to zero:
#+begin_src asm
  movzbl (%rsi), %eax       # %rax = 0-extended byte from memory
#+end_src
Writes to 32-bit registers automatically clear the upper 32 bits, so =%eax= here is enough.

** Clobbering =%rbx= without saving it
=%rbx= is a callee-saved register. If your function uses it without =push %rbx= / =pop %rbx= around the body, you'll corrupt the caller's =%rbx= silently. The same goes for =%rbp=, =%r12=, =%r13=, =%r14=, =%r15=.
#+begin_src asm
  myFunc:
      push %rbx             # save it first
      mov %rdi, %rbx        # now safe to use
      # ... do stuff ...
      pop %rbx              # restore before returning
      ret
#+end_src

** Using fd=0 when you meant fd=1
For the =write= syscall, stdout is file descriptor *1*, not 0. File descriptor 0 is stdin and writing to it often produces no visible output and no error — your program just silently does nothing. If "my program prints nothing", check the =%rdi= value before the =write= syscall.

** Forgetting that =cmp a,b= reads right-to-left in AT&T
In AT&T syntax, =cmp %rbx, %rax= does =%rax - %rbx= internally and sets flags based on that. So =jl label= jumps if =%rax < %rbx=, *not* if =%rbx < %rax=. Read the table back in the cmp/jmp section whenever you're unsure — I still do.

** Stack not 16-byte aligned at =call=
If you call a function (especially a libc function like =printf=) and get a segfault inside it that makes no sense, 90% of the time it's because =%rsp % 16 != 0= right before the =call=. Re-read the stack alignment section above and double-check the math.

** Using signed jumps for unsigned comparisons (or vice versa)
=jl=/=jg=/=jle=/=jge= are signed comparisons. =jb=/=ja=/=jbe=/=jae= are unsigned. If you're iterating a loop counter against a length, you want unsigned (=jb= for "below"). If you compare a negative number with signed jumps you'll get the sign-aware answer; with unsigned jumps you'll get "negative numbers are enormous positive numbers" which is usually not what you want.

** Forgetting to actually exit
If your program falls off the end of =_start= without making an exit syscall, the CPU tries to execute whatever bytes come next in memory and you get a mysterious segfault. Always finish =_start= with =mov $60, %rax / syscall=.

* Common idioms
A handful of patterns show up in basically every x86-64 program — both compiler output and handwritten code. Recognizing them at a glance makes reading assembly much faster.

** Zeroing a register: =xor %reg, %reg=
#+begin_src asm
  xor %rax, %rax        # %rax = 0
#+end_src
XOR-ing a register with itself gives zero. You'll see this in basically every =_start= epilogue in this guide, zeroing out =%rdi= before the exit syscall. Why prefer it over =mov $0, %rax=?
+ /Shorter encoding/: 3 bytes vs. 7 bytes for =mov=.
+ /Faster/: the CPU recognizes this idiom specifically and can execute it without reading the register's old value, which breaks what would otherwise be a data dependency. On modern chips =xor %rax, %rax= is essentially free.

** Checking if a value is zero: =test %reg, %reg=
#+begin_src asm
  test %rax, %rax       # sets flags based on %rax
  je   someplace        # jump if %rax was zero
#+end_src
=test= computes the bitwise AND of its two operands and sets flags based on the result, but /throws away/ the result itself. When both operands are the same register, the AND is just the register's value, so the flags reflect whether the register is zero. Shorter and no slower than =cmp $0, %rax=, so it's the idiomatic way to test for zero. The =writeInt= function uses this to check if its input was negative.

** =leave= for the epilogue
=leave= is a one-byte shorthand for =mov %rbp, %rsp; pop %rbp=. You'll see it at the end of almost every function that set up a normal stack frame. The guide uses it throughout — it's purely a space/readability win, no performance difference.

** =inc= / =dec= for counters
#+begin_src asm
  inc %rcx              # equivalent to: add $1, %rcx
  dec %rdx              # equivalent to: sub $1, %rdx
#+end_src
Shorter encoding and very common in loops. One subtlety: =inc= and =dec= don't touch the carry flag, while =add= and =sub= do. In code that needs the carry flag (e.g. multi-word arithmetic), you'll see =add $1= instead. For normal counter loops, =inc=/=dec= is the idiom.

** =mov= between registers vs. =xor reg, reg=-then-=mov=
Sometimes you'll see things like:
#+begin_src asm
  xor %rax, %rax        # zero %rax
  mov %dil, %al         # put a byte in the low 8 bits
#+end_src
which is doing a zero-extended byte copy into =%rax=. This is almost always better written as =movzbq %dil, %rax=, but you might see the xor-then-mov pattern in older or handwritten code.

* Exercises
Here are a few exercises that exercise (ha) the specific concepts from this guide. I'd really encourage you to try each one yourself before peeking at the solution. Even if you just stare at the problem for a minute and think "how would I approach this?" before scrolling down, you'll get way more out of them.

Each one is small enough to fit in a single file. Build with:
#+begin_example
as -g ex.s -o ex.o
ld ex.o -o ex
./ex
echo $?
#+end_example
The last couple use =readInt= and =writeInt= from the guide — for those, link with the object files you've already built:
#+begin_example
ld ex.o readInt.o writeInt.o -o ex
#+end_example

** Exercise 1: Sign of a number
/Concepts: =cmp=, conditional jumps, three-way branch/

Write a program that loads some number into a register and exits with:
+ =1= if the number is positive,
+ =0= if it's zero,
+ =-1= (which will show up as =255=) if it's negative.

Change the value by hand in the source and re-assemble to test all three cases.

/Hint: you'll need a =cmp= against =$0= and two different conditional jumps (one for "greater than", one for "equal"). Everything else falls through to the negative case./

*** Solution
#+begin_src asm
          .text
          .global _start

  _start:
          mov $-42, %rax          # change to 0 or positive to test other branches
          cmp $0, %rax
          jg  positive
          je  zero
          # fall through: negative
          mov $-1, %rdi
          jmp done
  positive:
          mov $1, %rdi
          jmp done
  zero:
          mov $0, %rdi
  done:
          mov $60, %rax
          syscall
#+end_src

The key pattern: =cmp= against zero sets flags, then you pick conditional jumps based on which case you want to /skip to/ — the "default" case (negative, here) is whatever falls through when no jump is taken.

** Exercise 2: Sum from 1 to 10
/Concepts: loops, accumulators/

Compute =1 + 2 + ... + 10= and exit with the result (should be =55=). Use a counter register, an accumulator register, and a simple loop.

*** Solution
#+begin_src asm
          .text
          .global _start

  _start:
          xor %rax, %rax          # accumulator = 0
          mov $1, %rcx            # counter i = 1
  loop:
          cmp $10, %rcx
          jg  done                # i > 10, exit loop
          add %rcx, %rax          # sum += i
          inc %rcx                # i++
          jmp loop
  done:
          mov %rax, %rdi          # exit code = sum
          mov $60, %rax
          syscall
#+end_src

The shape of every counter loop in assembly: set up accumulator and counter → at the top, check the exit condition with =cmp= + conditional jump → do the body → =inc= the counter → =jmp= back. You'll write this pattern hundreds of times.

** Exercise 3: Max of an array
/Concepts: indexed addressing, looping over an array/

Hard-code an array of 5 integers in =.data=. Find the largest one and exit with it.

/Hint: start with =max = arr[0]=, loop from =i = 1= to the end, and update =max= whenever you find something bigger. The array length can be computed at assembly time with =(. - arr) / 8=./

*** Solution
#+begin_src asm
          .section .data
  arr:    .quad 7, 3, 11, 4, 9
  arrlen = (. - arr) / 8          # number of elements: 5

          .section .text
          .global _start

  _start:
          lea arr(%rip), %rbx     # base address
          mov (%rbx), %rax        # max = arr[0]
          mov $1, %rcx            # index i = 1
  loop:
          cmp $arrlen, %rcx
          jge done
          mov (%rbx, %rcx, 8), %rdx   # %rdx = arr[i]
          cmp %rax, %rdx          # compare current max with arr[i]
          jle skip                # if arr[i] <= max, skip
          mov %rdx, %rax          # new max
  skip:
          inc %rcx
          jmp loop
  done:
          mov %rax, %rdi
          mov $60, %rax
          syscall
#+end_src

Note the =(%rbx, %rcx, 8)= addressing mode — base + (index × element-size). This is the direct assembly counterpart to C's =arr[i]= for an array of 8-byte elements. If it were an array of 4-byte =.long= values, the scale would be 4.

** Exercise 4: Absolute value function
/Concepts: defining a function, calling conventions/

Write a function =abs= that takes an integer in =%rdi= and returns its absolute value in =%rax=. Call it from =_start= with some negative number and exit with the result.

/Hint: you don't need a stack frame for this — no locals, no call to other functions, no callee-saved registers. Just a conditional =neg= and a =ret=./

*** Solution
#+begin_src asm
          .text
          .global _start

  # abs(x): returns |x|. x in %rdi, result in %rax.
  abs:
          mov %rdi, %rax
          cmp $0, %rax
          jge abs_done
          neg %rax
  abs_done:
          ret

  _start:
          mov $-42, %rdi
          call abs
          mov %rax, %rdi          # expect 42
          mov $60, %rax
          syscall
#+end_src

This is the minimal shape of a function: label → do the work → =ret=. No prologue/epilogue because we don't need a stack frame. This only works when your function (a) doesn't need local variables, (b) doesn't call any other function, and (c) doesn't use callee-saved registers. Violate any of those and you need the full =push %rbp / mov %rsp, %rbp / leave / ret= song and dance.

** Exercise 5: Function with local variables
/Concepts: stack frames, locals at negative offsets from =%rbp=/

Write a function =diffsq(a, b)= that computes =(a + b)² - (a - b)²= using two local variables on the stack — one for =(a+b)²= and one for =(a-b)²=. Return the result.

(Yes, algebraically this equals =4ab=, so you could do it without locals. The point is to practice using stack slots!)

/Hint: standard prologue, allocate 16 bytes (two 8-byte locals, and 16 keeps the stack aligned), store your intermediates at =-8(%rbp)= and =-16(%rbp)=, and use =leave; ret= at the end./

*** Solution
#+begin_src asm
          .text
          .global _start

  # diffsq(a, b) = (a + b)^2 - (a - b)^2   (which equals 4*a*b)
  # a in %rdi, b in %rsi, returns in %rax.
  diffsq:
          push %rbp
          mov %rsp, %rbp
          sub $16, %rsp           # two 8-byte locals, keeps %rsp aligned

          # local at -8(%rbp) = (a + b)^2
          mov %rdi, %rax
          add %rsi, %rax
          imul %rax, %rax
          mov %rax, -8(%rbp)

          # local at -16(%rbp) = (a - b)^2
          mov %rdi, %rax
          sub %rsi, %rax
          imul %rax, %rax
          mov %rax, -16(%rbp)

          # return local[0] - local[1]
          mov -8(%rbp), %rax
          sub -16(%rbp), %rax

          leave
          ret

  _start:
          mov $3, %rdi
          mov $5, %rsi
          call diffsq
          mov %rax, %rdi          # expect 4 * 3 * 5 = 60
          mov $60, %rax
          syscall
#+end_src

The useful thing to get comfortable with here is the mental map from "local variable" to "address at a negative offset from =%rbp=". A C compiler would generate essentially this same code for =long c = a + b; c = c*c;= — the =c= lives at =-8(%rbp)=.

** Exercise 6: Recursive factorial
/Concepts: recursion, stack alignment, saving arguments across recursive calls/

Write =fact(n)= that recursively computes =n!=. Base case: =fact(0) = fact(1) = 1=. Recursive case: =fact(n) = n * fact(n-1)=.

/Hint: this is very similar to =fib= from the guide. The tricky part is that you need =n= both before and after the recursive call (you need =n= to compute =n-1= for the recursion, and you need =n= again to multiply by the result). Save =n= in a local stack slot — don't =push %rdi= before the call, because that would misalign the stack for =call fact=./

*** Solution
#+begin_src asm
          .text
          .global _start

  # fact(n): returns n!. n in %rdi, result in %rax.
  # Stack frame layout (below %rbp):
  #   -8 : saved copy of n across the recursive call
  fact:
          push %rbp
          mov %rsp, %rbp
          sub $16, %rsp           # 16-byte aligned; -8 used for saved n

          cmp $1, %rdi
          jle fact_base

          mov %rdi, -8(%rbp)      # save n in a local slot
          dec %rdi                # compute (n - 1)
          call fact               # %rax = (n - 1)!
          mov -8(%rbp), %rdi      # reload n
          imul %rdi, %rax         # %rax = n * (n - 1)! = n!

          leave
          ret

  fact_base:
          mov $1, %rax            # 0! = 1! = 1
          leave
          ret

  _start:
          mov $5, %rdi
          call fact
          mov %rax, %rdi          # expect 5! = 120
          mov $60, %rax
          syscall
#+end_src

The key subtlety: the temptation is to write =push %rdi / dec %rdi / call fact / pop %rdi=, which feels natural. But that =push= moves =%rsp= by 8 bytes, so =%rsp % 16 == 8= at the =call=, which violates the ABI. In this particular example nothing crashes because the callee doesn't use instructions that require alignment — but it's modeling the wrong pattern. Stash =n= in a local slot you already allocated instead.

One more note: =fact(n)= overflows a 64-bit register at =n = 21=. So this program works for =n= up to 20. Exit codes are truncated to a byte, so you won't see the full result for =n >= 6= unless you use =writeInt= (see the next exercise).

** Exercise 7: Sum of 1 to N, with I/O
/Concepts: putting it all together — read input, loop, write output/

Write a program that reads an integer =N= from stdin using =readInt=, computes =1 + 2 + ... + N=, and prints the result using =writeInt=.

/Hint: this is just Exercise 2 with two changes — get =N= from =readInt= instead of hardcoding 10, and call =writeInt= instead of stuffing the result into the exit code./

*** Solution
#+begin_src asm
          .text
          .global _start
          .extern readInt
          .extern writeInt

  _start:
          call readInt            # N -> %rax
          mov %rax, %rcx          # %rcx = counter, starts at N
          xor %rax, %rax          # %rax = running sum
  sum_loop:
          test %rcx, %rcx
          jz   sum_done           # counter hit 0, done
          add %rcx, %rax          # sum += counter
          dec %rcx                # counter--
          jmp sum_loop
  sum_done:
          mov %rax, %rdi
          call writeInt

          xor %rdi, %rdi
          mov $60, %rax
          syscall
#+end_src

Build and run:
#+begin_example
as ex7.s -o ex7.o
ld ex7.o readInt.o writeInt.o -o ex7
echo 100 | ./ex7
#+end_example
Expected output: =5050=.

Small stylistic thing to notice: this version loops /down/ from =N= to =1= instead of up from =1= to =N=. That way we don't need a separate termination register — we just loop until the counter hits zero, which =test %rcx, %rcx / jz= checks cheaply. Little tricks like this come naturally once you've written enough loops.

* Full calling convention reference
This is the stuff you /need/ while writing a function but don't want to re-read every time. Bookmark this section.

** Passing arguments
Integer/pointer arguments go in these registers, in order:
+ =%rdi= (1st)
+ =%rsi= (2nd)
+ =%rdx= (3rd)
+ =%rcx= (4th)
+ =%r8= (5th)
+ =%r9= (6th)

Any arguments beyond the 6th go on the stack, pushed in reverse order.

** Return values
+ Integer/pointer return value goes in =%rax=.
+ 128-bit return values use =%rax= (low) and =%rdx= (high).
+ Floating-point return values go in =%xmm0=.

** Caller-saved registers
These can be clobbered by any function you call. If you care about their value across a call, save them yourself (usually by pushing them before the =call= and popping after).
+ =%rax=, =%rcx=, =%rdx=
+ =%rsi=, =%rdi=
+ =%r8=, =%r9=, =%r10=, =%r11=

** Callee-saved registers
If your function wants to use any of these, it must save and restore them (typically with =push= at the top and =pop= at the bottom).
+ =%rbx=
+ =%rbp=
+ =%r12=, =%r13=, =%r14=, =%r15=

=%rsp= is of course always preserved — a function that leaves =%rsp= in a different place than it found it is broken.

** Standard prologue and epilogue
#+begin_src asm
  fun:
          push %rbp               # save the caller's base pointer
          mov  %rsp,%rbp          # set up this frame's base pointer
          sub  $N,%rsp            # make room for N bytes of locals (multiple of 16)
          ## ... function body ...
          leave                   # shorthand for: mov %rbp,%rsp; pop %rbp
          ret
#+end_src

Remember: =sub $N, %rsp= where N is a multiple of 16, to keep the stack aligned for any =call= instructions in the body.

** Syscall calling convention
Syscalls look a lot like function calls — but they're different in ways that will bite you if you confuse the two.

+ The syscall number goes in =%rax= (not in =%rdi= like a function argument).
+ Arguments go in =%rdi=, =%rsi=, =%rdx=, =%r10=, =%r8=, =%r9= — in that order. A maximum of 6.
+ *The 4th argument is =%r10=, not =%rcx=.* This is the single biggest difference between syscall and function-call conventions, and it's very easy to get wrong if you're used to calling C functions. The =syscall= instruction clobbers =%rcx= (it stashes the return address there), which is why the ABI couldn't use it.
+ Return value comes back in =%rax=. A negative result (roughly −4095 ≤ rc < 0) indicates an error, and its absolute value is the =errno= code.
+ The kernel clobbers =%rcx= and =%r11=. Everything else (including all the argument registers) is preserved across the =syscall= — you don't need to save them yourself.
+ The stack does /not/ need to be 16-byte aligned for =syscall= the way it does for =call=.

This guide uses three syscalls — 0 (=read=), 1 (=write=), 60 (=exit=) — all of which take three or fewer arguments, so you don't hit the =%r10= gotcha. But if you ever reach for =mmap= (9), =pread64= (17), =select= (23), or anything else with four or more args, remember to load the fourth arg into =%r10=.

For a full list of syscall numbers and their argument lists, see =/usr/include/asm/unistd_64.h= or run =man 2 syscall=.

* Floating point and vector registers (reference)
You don't need these for the main assignments, but they're good to know about for the future and for your own reference.
** Floating point registers
 x86-64 has specialized registers for floating-point arithmetic. In modern x86-64 systems, floating-point operations typically use the SSE/SSE2 instruction set rather than the older x87 FPU stack-based approach.

 SSE/SSE2 Floating Point Registers:
 + =%xmm0= – =%xmm15=: 128-bit registers used for scalar and packed floating-point operations
   + Each can hold:
     - One double-precision (64-bit) float
     - One single-precision (32-bit) float
     - Two double-precision floats (packed)
     - Four single-precision floats (packed)

 Common floating-point instructions:
 + =movss= / =movsd=: Move scalar single/double precision values
 + =addss= / =addsd=: Add scalar single/double precision
 + =subss= / =subsd=: Subtract scalar single/double precision
 + =mulss= / =mulsd=: Multiply scalar single/double precision
 + =divss= / =divsd=: Divide scalar single/double precision
 + =ucomiss= / =ucomisd=: Compare (unordered) single/double precision

 Example:
 #+begin_src asm
   # Add two double-precision floats
   movsd value1(%rip), %xmm0   # Load first float into %xmm0
   addsd value2(%rip), %xmm0   # Add second float to %xmm0
   movsd %xmm0, result(%rip)   # Store result
 #+end_src

 Calling convention for floating-point:
 + First 8 floating-point arguments are passed in =%xmm0= – =%xmm7=
 + Floating-point return values go in =%xmm0=
 + All =%xmm= registers are caller-saved (must be preserved by caller if needed)

** Vector registers
 x86-64 supports various SIMD (Single Instruction, Multiple Data) extensions for parallel processing:

 SSE/SSE2 Registers (already mentioned above):
 + =%xmm0= – =%xmm15=: 128-bit registers
 + Can process multiple data elements in parallel
 + Example: Add 4 floats or 2 doubles simultaneously

 AVX (Advanced Vector Extensions) Registers:
 + =%ymm0= – =%ymm15=: 256-bit registers
 + Lower 128 bits overlap with corresponding =%xmm= registers
 + Can process:
     - 8 single-precision floats
     - 4 double-precision floats
     - Various integer types in parallel

 AVX-512 Registers (on supported CPUs):
 + =%zmm0= – =%zmm31=: 512-bit registers
 + Lower 256 bits overlap with =%ymm= registers
 + Can process:
     - 16 single-precision floats
     - 8 double-precision floats
     - Up to 64 bytes of integer data in parallel
 + Additional mask registers =%k0= – =%k7= for conditional operations

 Common use cases:
 + High-performance computing
 + Graphics and image processing
 + Scientific computations
 + Machine learning operations
 + Audio/video encoding

 Example AVX-512 usage (see assembly-examples/06-advanced/01-avx512.s):
 #+begin_src asm
   # Add 16 single-precision floats in parallel
   vmovaps array1(%rip), %zmm0     # Load 16 floats
   vmovaps array2(%rip), %zmm1     # Load 16 floats
   vaddps %zmm0, %zmm1, %zmm2      # Add them all at once
   vmovaps %zmm2, result(%rip)     # Store result
 #+end_src

 Note: Vector instructions require CPU support. Check with =cpuid= instruction or =/proc/cpuinfo= on Linux.
 Most modern x86-64 CPUs support at least SSE2, many support AVX2, and newer server/workstation CPUs support AVX-512.
